# 布隆过滤器

- 概念：由二进制位图和k个独立的哈希函数组成，空间高效的概率型集合成员判断，在集合里的一定返回true，不在集合里的有一定概率返回true（误判）
- 增删改查：
  - 查询：计算k个哈希下标，全部是0说明元素一定不存在，全部都是1元素可能存在
  - 插入：对元素计算k个哈希值，把对应k个bit置为1
  - 不支持删除：多个元素可能共享同一个bit，直接清零会影响其他元素
  - 不支持修改：没法删除怎么修改
- 复杂度：
  - 插入查询都是O(k)，k是哈希函数个数，是常数时间
- 优点：
  - 节省内存
- 缺点：
  - 会误判
- 应用：
  - 海量数据判存、去重
- 注意：
  - 操作的都是下标所以注意使用size_t不用int/unsigned int
  - `vector<bool>`动态实现时注意不能有默认构造函数
- 实现：BloomFilter.cpp
# 双向链表
- 概念：线性链式存储结构，**每个节点除了保存数据、后继指针`next`，还保存前驱指针`prev`**，可以正向、反向遍历

``` txt
[prev | data | next] ↔ [prev | data | next] ↔ [prev | data | next]
```

- 增删改查：
  - 查询：根据值或索引查找，遍历链表
  - 插入：把新节点prev、next设置完成，修改旧链表指针，注意判定边界nullptr
  - 删除：根据值需要遍历，给定节点可以直接删除，注意判定边界nullptr
  - 修改：先查找，再直接修改value
- 复杂度：
  - 查询：O(n)
  - 插入：O(n)/O(1)
  - 删除：O(n)/O(1)
  - 修改：O(n)
- 优点：
  - 双向遍历
  - 头尾插入删除效率高O(1)
- 缺点：
  - 内存额外开销
  - 不支持随机访问，查询效率低O(n)
- 应用：
  - std::list、LRU、任务调度
- 注意：
  - 实际工程常用**dummy 虚拟哨兵节点**，虚拟头节点不存储有效业务数据，永远不为空
- 实现：DoubleLinkedList.cpp
# 哈希表（散列表）
- 概念：空间换时间，利用**哈希函数**把 key 映射到数组下标，平均时间复杂度 O (1) 完成增、删、查，`index = hash(key) % bucket_num`
- 组件：
  - 哈希函数 hash (key)：输入任意 key（int、string、自定义对象），输出整数索引，好的哈希函数应当计算快且散列均匀，雪崩效应：key 微小改动，哈希值差异很大
  - 哈希冲突：不同 key 经过哈希得到相同下标，冲突无法完全避免
  - 负载因子 load_factor：有效元素个数 / 桶总数量，常用阈值 **0.75**，超过触发**rehash 扩容**
- 冲突解决：
  - 链地址法（常用）：每个桶存放一条链表；哈希冲突的元素挂到同一个桶的单向链表后面，C++11 后链表长度过长，自动转为红黑树，退化到 O (logn)
  - 开放寻址法：冲突发生，在数组内部向后找下一个空闲位置存放，全部数据存在数组，缓存友好，没有额外指针，删除不能直接置空，需要标记删除
- 扩容 rehash：rehash 过程迭代器会失效
  - 负载因子超过阈值，开辟**更大的新数组**（一般翻倍）
  - 遍历旧表全部元素，重新哈希，迁移到新桶
  - 释放旧数组，切换哈希表
- 增删改查：
  - 查询：哈希算出桶编号，遍历对比 key
  - 插入：对 key 做哈希，计算桶下标，遍历该桶链表，key 已存在则更新 value；不存在则新建节点插到桶链表中（头或尾），数目过多触发rehash
  - 删除：哈希算出桶下标，遍历找到目标 key，链表移除节点，释放节点内存
  - 修改：哈希定位桶，遍历链表，key 已存在则更新 value，不存在则新建节点插到桶链表中
- 复杂度：最坏都是O(n)（同一个桶）
  - 查询：O(1)
  - 插入：O(1)
  - 删除：O(1)
  - 修改：O(1)
- 优点：
  - 平均增删改查O(1)，速度快
  - 不要求 key 有序，适合判断键值对是否存在
  - 支持很大范围的 key
- 缺点：
  - 最坏性能退化
  - 无序
  - 哈希函数选择不当会导致性能暴跌
  - rehash 扩容瞬间开销大
- 应用：高频查找、去重、数据库索引、无序容器
- 注意：
  - 因为是单向链表删除需要保存前置节点
- 实现：HashTable.cpp
# 红黑树
- 概念：**自平衡二叉搜索树 (BST)**，底层是二叉搜索树，通过颜色规则维持大致平衡（非绝对平衡），树比较高
- 特性：
  - 二叉搜索树：左小右大二叉树，输入有序数据退化成链表O(n)
  - 每个节点不是红色就是黑色
  - 根节点黑色
  - 所有叶子节点黑色
  - 红节点的孩子必须都是黑色（红红相连禁止）
  - 任意节点到所有后代叶子节点路径上黑色节点数量相同（黑高一致）
- 旋转：只改变树结构，用于修复红黑树性质，只修改几个指针O(1)
  - 左旋（右孩子上位）：以 x 为轴，x 的右孩子 y 向上顶替，y 的左子树交给 x 当右孩子
  - 右旋（左孩子上位）：以 y 为轴，y 的左孩子 x 向上顶替，x 的右子树交给 y 当左孩子

  ``` txt

        X                    Y
      /   \                /   \
     T1    Y     ───▶     X     T3
          / \            / \
         T2  T4         T1 T2
  右旋
        Y                    X
      /   \                /   \
     X    T4    ───▶     T1    Y
    / \                        / \
   T1 T2                      T2 T4
  ```
- 树的三种遍历：
  - 前序遍历：访问当前节点-递归左子树-递归右子树
  - 中序遍历（最重要）：递归左子树-访问当前节点-递归右子树，BST严格升序
  - 后序遍历：递归左子树-递归右子树-访问当前节点

# B+树/B树
- 概念：多路平衡查找树，绝对平衡，树比较矮
- 特性：m阶B+树
  - 内部结点满足：children.size() == keys.size() + 1，分隔键语义是\<=，实例：`// 设 keys = {10, 20}，则有 3 个孩子：孩子0 装所有 <10 的键，孩子1 装 [10,20)，孩子2 装 ≥20 的键。`
  - 节点与key数的规律：
    - 根节点：
      - 索引：节点数：\[2,m\]，key数：\[2,m\]
      - 叶子：节点数：无意义，key数：\[1,m-1\]
    - 索引节点：节点数：\[ceil(m/2),m\]，key数：\[ceil(m/2),m\]
    - 叶子节点：节点数：无意义，key数：\[ceil(m/2)-1,m-1\]
  - 所有叶子节点在同一层，用双向链表串联，key全局有序，且真实key都在叶子上，树枝上是逻辑key，是叶子key的副本
  - 非叶子节点只存key，叶子节点保存完整数据或指针
  - key是唯一不重复的
- 与B树的区别：
  - 数据：B树每个节点都保存真实key和数据
  - 子节点：B树子节点数=key数+1
  - 查询：B树命中就返回
  - 叶子：B树叶子间独立
  - 磁盘利用：B+树磁盘顺序存储性能更高
- 陈旧分隔键：删除某个叶子最小键之后，内部结点里指向它的旧分隔键会变成一个"陈旧"分隔键，但它仍然小于右子树里剩余的每个键，因此查找路由依然正确，无需向上清理
- 增删改查：
  - 查询：
    - 等值查询：从根节点二分，向下路由到叶子节点取数据
    - 范围查询：\[a,b\]先查找到a的叶子节点，然后沿着链表向后遍历到b结束
  - 插入：
    - 找到合适插入位置
    - 叶子节点未满，可以直接插入
    - 叶子节点已满（key数达到m-1），分裂
      - 原叶子保留前一半 key；新叶子拿后半部分 key
      - 将**新叶子第一个 key 添加到父索引节点**作为分隔 key
      - 更新叶子双向链表指针
    - 如果父索引节点插入 key 之后也满了，继续向上分裂；一直到根节点；根分裂树高度 + 1
  - 删除：
    - 找到待删除节点key
    - 删除后`key>=ceil(m/2)-1`，可以直接删除
    - 删除后`key<ceil(m/2)-1`，需要补充
      - 左右兄弟节点充足：从兄弟那挪一个key过来，更新父节点分隔key
      - 左右兄弟节点不足：两个节点合并，删除父节点分隔key
    - 父节点如果 key 过少，继续向上处理（借 / 合并），一直传到根
  - 修改：等于删除+插入
- 复杂度：h=树高，一般为2-4
  - 查找：O(h)
  - 插入：O(h)
  - 删除：O(h)
  - 修改：O(h)
- 优点：
  - 空间局部性，磁盘顺序读取，IO少
  - 范围查询、排序、分组极强
  - IO稳定
- 缺点：
  - key存在多份副本，有少量冗余
- 应用：MySQL索引
- 注意：
- 递归释放需要先释放孩子，再删除自己（后序遍历），否则会留下悬空指针
- 
- 实现：BPlusTree.cpp
# 跳表
- 概念：有序链表 + 多层索引，跳表建立多层稀疏索引，高层快速跳过一大批节点，提高搜索速度
- 特性：
  - 底层原始链表保存全部真实数据
  - 随机化思想：插入时随机生成节点层数
  - 也有哨兵头节点head
- 增删改查：
  - 查找：
    - 哨兵最高层开始查找
    - 当前层如果下一个节点`key<target`，往右走
    - 否则下降一层，继续往右走
    - 直到0层结束
  - 插入：
    - 需要准备前驱节点数组update\[\]
    - 哨兵最高层开始查找，每层找到插入点前一个节点，存入 update \[i\]，依次往下遍历
    - 生成新节点，层数随机生成
    - 如果层数高于最高层，更新当前最高层数
    - 每层执行插入
  - 删除：
    - 需要准备前驱节点数组update\[\]
    - 哨兵最高层开始查找，每层找到插入点前一个节点，存入 update \[i\]，依次往下遍历
    - 在0层看有没有找到目标key
    - 不存在，直接返回
    - 存在，遍历每一层update，如果有相等的需要跳过该节点
    - 如果head最高层数指向nullptr，降低最高层数
  - 修改：先删再插
- 复杂度：最坏是O(n)
  - 查找：O(log n)
  - 插入：O(log n)
  - 删除：O(log n)
  - 修改：O(log n)
- 优点：
  - 实现简单
  - 范围查询友好
  - 并发友好
- 缺点：
  - 有最坏情况发生
  - 节点分散，磁盘IO大
  - 原生单向不支持反向遍历
- 应用：Redis 有序集合 zset
- 注意：
  - cur_level表示当前最大层数，kMaxLevel是硬限制最大层数，下标从0到cur_level-1哦
- 实现：SkipList.cpp
